# Конструктор курсов — текущее состояние

Версия 0.10.4, 2026-11-04. Браузерное приложение, GitHub Pages:
https://kabdykarimovaidyn-svg.github.io/konstruktor/
Пользователь разрешил реализовать и опубликовать согласованные изменения.

## Решения и область работ
- Название пока «Конструктор курсов»; новое название не выбрано.
- По умолчанию бело-синее деловое оформление. Один курс объединяет видео и практику.
- Старые проекты schema:2 сохраняются. Локальные проекты/профиль — IndexedDB,
  без облачного входа. Импорт/экспорт проекта включает медиа.
- Сортировка в последовательном режиме меняет переходы; в режиме ветвлений сохраняет связи.
- Редактор чужих готовых SCORM (включая iSpring) отложен на отдельный этап.
- Предложения без согласия пользователя (ИИ, облако, версии, дополнительные жесты,
  автоматические подсказки, выравнивание/блокировка областей и прочее) не входят в v0.6.

## Реализовано до v0.6
- Видео, скриншоты, несколько полей, горячие области, вопросы, текст/разбор, возврат.
- Ручная карта с портами/связями, группами, масштабом, поиском и авторасстановкой.
- Последствия решения могут идти через несколько видео и разбор, затем возврат к
  тому же выбору без повторного вводного видео; правильная ветка продолжает курс.
- Удаление/переименование/копирование шагов, пакетная загрузка, перетаскивание шагов
  и разделов, отмена/повтор. Несколько проектов, корзина и восстановление.
- Общий плеер для предпросмотра и SCORM 1.2. ZIP с медиа и манифестом без внешних запросов.
- Восстановление шага, позиции видео, числа ошибок. Оценка 100 минус штрафы.
- Явное «Завершить»: commit и LMSFinish; при отказе — повтор. Предпросмотр закрывается.
  Встроенный контейнер закрывает LMS; стандарт SCORM 1.2 не гарантирует закрытие iframe.
- Проверка match между полями по стабильным ID, включая регистр и пробелы;
  для сравнения в suspend_data сохраняются соль и отпечатки, а не текст пароля.

## Согласованные доработки v0.6 — реализовано
- Шапка задания: отдельное название задания, заметное «Задание», затем инструкция.
  Авторские названия шагов/файлов по-прежнему скрыты от сотрудника.
- Оформление курса: логотип PNG/JPG/WebP до 3 МБ, общий шрифт, основной цвет,
  цвет заголовков/текста. Параметры включаются в предпросмотр и SCORM.
- Начальная страница: название курса, логотип, описание, центральная кнопка «Начать».
  Новые пустые курсы получают её автоматически. В старом курсе добавляется через
  «Добавить материал → Начальная страница», без неявной перестройки старых веток.
- Шаблоны инструкции, карточек, диалога; редактируемый текст. Оформленный итог
  берёт название курса автоматически.
- Интерактивное видео: кнопки на последнем кадре или на заданной секунде с паузой;
  расположение/размер областей мышью, цвет кнопки и текста, размер шрифта, скругление.
  Полноэкранный режим включается для общего контейнера, сохраняя варианты при переходах.
  Работает при разрешении браузера/LMS; на устройстве без Fullscreen API доступен обычный режим.
- Прогресс: синяя сегментированная полоса сверху, сегмент на страницу маршрута.
  Для линейного курса — все страницы. Для веток — пройденные страницы и предполагаемый
  кратчайший оставшийся маршрут; пересчитывается после выбора. Возврат не дублирует сегменты.
- Новые проверки текста: несколько допустимых значений с новой строки, диапазон
  включительно (поддерживаются точка и запятая), формат почты/телефона; регистр и пробелы.
- Действия на экране: список, галочка, группа radio; начальное и правильное состояние.
  Несколько разных элементов на одном скриншоте, единая проверка перед продолжением.
- Autofill: источник «предыдущий шаг → поле», независимо от match. До 8 источников,
  по 64 символа. Значения Autofill сохраняются открытым текстом в данных прогресса LMS,
  о чём написано в настройках. Источники-пароли запрещены. Сравнение паролей остаётся хешированным.
  Исходное поле должно быть обязательным предшественником на всех ветках.
- Холст: копирование Ctrl/Cmd+C/V, перемещение стрелками (0.25%), изменение размера
  за восемь маркеров, масштаб 50–200%, Shift-выделение группы (также через список элементов),
  групповое перемещение/копирование/удаление. Справа — свойства выбранного элемента.
  Ссылки внутри скопированной группы получают новые ID. Горячие клавиши не мешают вводу текста.
- Новый учебный пример «Пример новых элементов»: готовая форма для проверки всех новых полей.
- Конвертер SCORM справа сверху, доступен и на главной. MP4 либо статический PPTX →
  видимая структура «обложка → материал/слайды → завершение», название, описание,
  цвет, шрифт и логотип. Открытие результата в редакторе или скачивание SCORM.
  Результат сохраняется отдельным проектом.

## Честные ограничения конвертера
- Прямой старый бинарный .ppt не поддержан: сначала сохранить как .pptx в PowerPoint.
  Полноценному преобразованию .ppt нужен отдельный движок/сервер, которого на GitHub Pages нет.
- PPTX импортируется локально в статические SVG: базовые тексты, фигуры, растровые
  изображения, часть мастер-слайдов. Это не движок PowerPoint: шрифты, переносы и
  сложная графика могут отличаться. Диаграммы/SmartArt/таблицы, анимации, переходы,
  встроенная озвучка/видео не воспроизводятся; в интерфейсе есть предупреждения.
  Перед публикацией автор обязан проверить слайды в предпросмотре.
- Кодеки MP4/WebM не конвертируются. Предпочтителен MP4 H.264. Автозапуск может
  требовать нажатия Play из-за политики браузера.
- 250 МБ медиа на проект; ZIP/JSON собираются в памяти. Нет ZIP64, SCORM 2004 и серверного хранения.
- Точное оформление и сценарии конкретной презентации проверяются на реальном файле.
- Совместимость с Mirapolis требует повторного тестового импорта нового ZIP.

## Структура
- model.js — проект, последовательность/граф, ссылки и адаптер курса.
- fields.js — общий контракт полей/ссылок для редактора и экспорта.
- player.js — общий автономный плеер; scorm.js — упаковка/API LMS.
- app.js — координация; outline.js — список; map.js — карта.
- areas.js — холст; field-ui.js — свойства выбранного элемента.
- course-ui.js — оформление; converter.js — поток конвертера; pptx.js — статический импорт.
- storage.js — IndexedDB/проекты; projects.js — библиотека/профиль; samples.js — пример.
- index.html, assets/css/author.css — каркас и оформление. dist/index.html генерируется.

## Согласовано на будущее — 2026-11-10

1. Три режима одного тренажёра. «Показ» подсвечивает действие и объясняет его.
   «Практика» даёт подсказку по запросу и позволяет повторить шаг.
   «Проверка» использует похожее задание с другими данными, без подсказок, с разбором в конце.
2. Обратная связь по конкретной ошибке. Автор задаёт для поля или действия объяснение
   и способ исправления. В видеоветках разбор может идти после сцены с последствиями.
3. Итог по навыкам. Автор привязывает шаги к навыкам, сотрудник видит, что сделал
   самостоятельно и где понадобилась помощь. Передачу детализации в Mirapolis
   нужно проверить отдельно.
4. Копирование оформления кнопки выбора поверх видео. Автор переносит цвет кнопки
   и текста, размер шрифта, скругление и размеры кнопки на другие кнопки.
   Текст, положение и переход каждой кнопки сохраняются.
5. Перетаскивание и сортировка на экране тренажёра. В меню «Добавить действие»
   разместить один пункт «Перетаскивание и сортировка» в группе «Дополнительные».
   После выбора в правой панели предложить два режима: «Распределить по зонам»
   и «Расставить по порядку». Автор задаёт элементы и зоны на холсте, а также
   допустимое распределение или правильный порядок. Участник может перемещать
   элементы мышью, касанием или кнопками, а результат проверяется по подтверждению.
6. Обязательно: вкладки и раскрывающиеся блоки. Автор настраивает содержимое
   каждого состояния. При переключении сотрудник остаётся на том же шаге,
   а введённые значения сохраняются.
7. Обязательно: имитация поиска. Автор задаёт запросы, результаты и действие
   при выборе записи, а также состояние «Ничего не найдено».
8. Обязательно: состояния полей и кнопок. Автор задаёт, когда элемент виден,
   скрыт, доступен или заблокирован, по значениям полей и действиям сотрудника.
9. Всплывающие окна и подтверждения. Автор задаёт, какое действие открывает окно,
   и настраивает результат подтверждения. Отмена закрывает окно и сохраняет
   заполненные данные формы.
   Автор может выделить и обрезать прямоугольный фрагмент снимка, сохранив
   исходник. Фрагмент размещается поверх основного скриншота как окно, которое
   открывается по клику на заданную область. Внутри можно разметить поля и кнопки.
   При закрытии окна введённые на основном экране данные сохраняются.
10. Связанные списки. Варианты во втором списке зависят от выбора в первом.
    При смене первого значения несовместимый выбор во втором сбрасывается.


11. «Переход» в меню «Добавить действие». Автор рисует кликабельную область
    поверх кнопки или вкладки и выбирает целевой шаг со скриншотом по названию.
    На одном экране можно добавить несколько таких областей с разными целями.
    Для обратной навигации автор размечает переходы и на целевых экранах.
    При переходе текущее состояние полей сохраняется автоматически в рамках
    прохождения. При возврате восстанавливаются даже частично введённый текст
    и выбранные значения. Переход не требует подтверждения или проверки полей.
    «Переход» открывает другой шаг, а запланированные вкладки из пункта 6
    переключают содержимое на одном шаге с сохранением введённых данных.

## v0.8.2: переходы и обрезка скриншотов
- «Переход» — область на экране тренажёра с целью на другом скриншоте.
  Видна на карте и работает в предпросмотре и SCORM. При возврате значения полей
  восстанавливаются в текущем сеансе плеера без проверки и записи в LMS.
- «Обрезать скриншот / вырезать окно» сохраняет фрагмент отдельным шагом.
  Если выбран основной экран, конструктор накладывает фрагмент на его копию
  в том же месте и затемняет фон. Исходные снимки сохраняются. Для открытия
  автор рисует «Переход», для закрытия размечает кнопку возврата на основном
  маршруте шага или отдельную область «Переход». Поля окна размечаются на новом шаге.

## v0.8.3: размер списков, переход на финал и пояснения

- Область «Переход» может открыть любой шаг, включая завершение курса.

- Вместо «шаг недостижим» показано, почему сотрудник не увидит экран и какие
  связи проверить. Отдельно поясняется, что это предупреждение, допускающее экспорт.

## v0.8.4: видимость задания и областей
- Инструкция выводится целиком, без кнопки раскрытия. Для очень длинного текста
  доступна прокрутка страницы, рабочая область сохраняет минимальную высоту.
- Области нажатия и поля на скриншотах имеют синюю обводку и мягкую пульсацию.
  При reduced-motion остаётся статическая подсветка.
- Нативный выпадающий список использует читаемый шрифт 12–18 px, независимо
  от длины и количества пунктов; длинный список прокручивается браузером.
- Для form/click добавлена настройка showNext. При отсутствии настройки
  кнопка снизу скрыта, если есть переходы или область проверки на скриншоте.

## v0.10.0: фигуры и текст поверх скриншота
- В правой панели «Фигуры и текст»: текстовый блок, прямоугольник, овал,
  треугольник, стрелка и линия. Область рисуется мышью, затем перемещается
  и масштабируется за края. Доступны копирование, стрелки и удаление.
- «Свойства объекта» содержит текст и название. «Оформление» справа настраивает
  выбранный объект: цвет, заливку, обводку, поворот; у текста — шрифт, размер,
  автоподбор, начертание и выравнивание. Общий дизайн остаётся во вкладке «Настройки».
- Без внешних ресурсов: модуль visuals.js используется в редакторе, предпросмотре
  и встраивается в SCORM. Объекты не перехватывают нажатия сотрудника.

## v0.10.1: единая палитра и прямой поворот
- Текст, фигуры и интерактивные инструменты сгруппированы внутри «Добавить элемент».
  Фигуры выбираются по пиктограммам. Кнопка над холстом открывает ту же палитру.
- Над выбранной фигурой есть ручка поворота; Shift фиксирует шаг 15°. В оформлении
  доступны поворот на 90° и сброс. Рамка поворачивается вместе с объектом.
- При изменении размера повёрнутой фигуры используются её локальные оси.
  Поворот одинаково применяется к объекту в редакторе, предпросмотре и SCORM.


## v0.10.2: список применённых элементов
- Все добавленные поля, списки, переходы, текст, фигуры и кнопки отображаются
  единым списком с точками сразу под «Добавить элемент», снаружи его раскрывающегося

  при его выборе в списке или на холсте.

## v0.10.3: выбор области без перехода
- «Добавить элемент → Выбор» создаёт field/kind:selection. Нажатие выделяет
  область полупрозрачным зелёным, повторное снимает выделение. Шаг не меняется,
  ошибки и проверка при нажатии не запускаются.
- Состояние сохраняется при переходах между скриншотами в текущем прохождении.
  В свойствах можно включить «Требовать выбор при проверке шага»; по умолчанию
  это необязательное выделение. Элемент доступен с клавиатуры как кнопка.

## v0.10.4: обязательный выбор перед областью перехода
- Область перехода использует ту же проверку формы, что и кнопка проверки.
  При наличии обязательной области «Выбор» она включена по умолчанию.
- Настройка перехода «Проверять задание перед переходом» позволяет включить
  проверку всех полей либо отключить её для свободной вкладки. Старые переходы
  без обязательного выбора сохраняют свободную навигацию.
- При пропущенном выборе шаг остаётся текущим и показано сообщение с названием
  обязательной области. При успехе открывается именно цель нажатой области.
