# SCORM module v2.0.0 — публичный контракт

При изменении интерфейса читать этот файл и assets/js/author/model.js.
Внутренний scorm.js не требуется читать или менять, если контракт не изменился.
Статус: реализован и проверен автоматически. Проверка в Mirapolis ещё не выполнена;
формальной сертификации SCORM нет. Называть совместимость подтверждённой пока нельзя.

## API

    const blob = await ScenaSCORM.build(course, assets);
    ScenaSCORM.validate(course); // true либо понятная ошибка

Результат — Blob application/zip, готовый для скачивания. Сборка работает в браузере
без сервера, библиотек и внешних запросов. ZIP без сжатия (видео уже сжато).
Весь архив собирается в памяти: крупные видео потребуют отдельного потокового решения.
ZIP64, шифрование и SCORM 2004 не поддерживаются.

## Course

    {
      id: 'my-course-v1', // ASCII: буквы, цифры, - и _, до 80 символов
      title: 'Мой курс',
      start: 'first',
      steps: [
        {id:'first', type:'input', title:'Имя', instruction:'Введите Айдын',
         label:'Имя', expected:'Айдын', error:'Проверьте имя', next:'end'},
        {id:'end', type:'end', title:'Завершение'}
      ]
    }

ID шагов уникальные; переходы ведут к существующим шагам. Из каждой достижимой
ветки должен существовать путь к завершению. Максимум 500 шагов.
Версию course.id менять при несовместимом изменении сценария, чтобы не восстанавливать
прогресс от предыдущего содержания.

## Типы шагов

- input: expected, label, next. Удаляются пробелы по краям; регистр не учитывается,
  кроме caseSensitive:true. rule:'url' дополнительно убирает http(s):// и конечный /.
  Проверка при Enter или кнопке. Текст ученика не передаётся в LMS.
- choice: options:[{label,next}] — кнопки. wrong:true оставляет на шаге и считает ошибку;
  error у варианта заменяет сообщение шага. selectBeforeContinue:true — радиокнопки
  и обязательная проверка после нажатия «Далее».
- click: background:'media/screen.png', rect:{x,y,w,h}, label, next.
  Координаты в процентах исходного изображения. Верная область — прозрачная кнопка;
  нажатие вне области показывает ошибку. Доступна клавиатурная активация области.
- video: src:'media/scene.mp4'; options:[{label,next}] или next.
  Кнопки появляются только после ended. Для последствий ошибки использовать обычный
  next на соответствующую видеосцену, а не wrong:true.
- end: завершает курс и передаёт completed и score в LMS.

Для input возможны background и rect: настоящее поле располагается поверх картинки,
кнопка подтверждения — под ней. Для click требуется скриншот, иначе экран условный.
У шага один проверяемый input/одна область. Несколько полей, отдельные координаты для
каждой кнопки choice и полноценная имитация произвольного приложения — будущий контракт.

## Assets

    {'media/screen.png': fileOrBlob, 'media/scene.mp4': uint8Array}

Допустимы Blob/File, ArrayBuffer, Uint8Array. Имена только media/ + ASCII имя файла.
Все src/background должны присутствовать в assets, внешние URL не принимаются.
Медиа копируются в пакет, формат и кодек не преобразуются и не проверяются.
Список файлов включается в манифест. Пример может смешивать видео и тренажёр в одном SCO.

## Состояние и оценка

SCORM 1.2 API ищется в родительских окнах и opener с ограничением глубины.
Инициализация, запись, commit, finish; сбои LMS отображаются ученику.
Данные: текущий шаг, число ошибок, результат и завершение. Возобновление через
cmi.suspend_data (лимит 4096 символов), cmi.core.lesson_location.
Не отправляются содержимое полей и персональные данные ученика.
Завершение — только end. Оценка: max(0,100−10×ошибки). Статус completed,
без порога passed/failed. Прогресс фиксируется после действий и при уходе со страницы.
Без LMS доступен просмотр с предупреждением: межсессионного сохранения нет.
Внутри видеосцены позиция не сохраняется; возобновление начинается с начала сцены.

## Проверки и границы

    node tests/scorm.test.cjs
    python3 scripts/check_scorm_zip.py

Тесты создают ZIP и проверяют сценарии, граф переходов, медиа, интерфейс адаптера,
LMSInitialize/SetValue/Commit/Finish, восстановление, недоступный API и отказ сохранения.
check_scorm_zip.py проверяет CRC, XML, ссылки на файлы и синтаксис проигрывателя.
Тестовые байты media — фикстуры упаковки, не проверка воспроизведения видео.
Общий проигрыватель проверен в браузере через предпросмотр конструктора.

Ручная приёмка в Mirapolis:
1. Импортировать scena-gmail-scorm12.zip в тестовый курс.
2. Пройти часть, допустить ошибку, закрыть и открыть: восстановлен шаг и счётчик.
3. Дойти до конца: статус завершён, оценка соответствует числу ошибок.
4. Проверить вложенный проигрыватель, новую вкладку и повторный запуск завершённого курса.
5. После добавления реальных медиа отдельно проверить видео, выбор на последнем кадре
   и точность полей поверх скриншота на разных размерах экрана.

Справочные источники:
https://scorm.com/scorm-explained/technical-scorm/run-time/run-time-reference/
https://scorm.com/wp-content/assets/cookbook/CookingUpASCORM_v1_2.pdf


## Дополнения v2
- player.js — единый проигрыватель для экспорта и предпросмотра; загрузить до scorm.js.
- ScenaSCORM.preview(course, urls) возвращает безопасно сформированный HTML для iframe
  (sandbox allow-scripts allow-same-origin allow-forms). urls — карта media/path → blob URL.
- form: fields:[{id,label,expected,rule:'exact'|'any'|'url',caseSensitive,rect}],
  background, submitRect (необязательно), button, error, next. Несколько полей,
  проверяются одновременно при Enter или кнопке. any требует непустой текст.
- choice: video:<ID видеошага> — кнопки поверх последнего кадра исходного видео.
  Такой выбор — отдельный узел графа, поэтому возврат не проигрывает вводное видео заново.
- message: body, button, next — ситуация/разбор/объяснение.
- return: next:<ID choice>, penalty:true — возврат прямо к выбору, одна ошибка за ветку.
  Если ошибка отложенная, не использовать wrong:true у исходного варианта.
- course.mode:'learn'|'test' определяет пояснение ошибок; penalty:0…100 — штраф за ошибку.
- Восстанавливается также позиция внутри видеосцены. Состояние v2 совместимо с v1.
- Медиаплеер использует штатные кодеки браузера. WebM с неизвестной длительностью
  может не дать восстановить последний кадр; MP4 с корректной длительностью предпочтителен.
- Координаты полей/областей нормализованы 0–100% и проверяются перед экспортом.
- Старый контракт input и video.options сохранён для совместимости с тестовыми пакетами.
